# Pairwise 训练方法对照结果

日期：2026-10-21。用户授权尝试 pairwise；具体时间配对契约、预设对照和后续补充见 [训练协议](PAIRWISE_TRAINING.md)。本轮只做同一验证日的开发实验，不是新独立测试或线上 CTR 实验。

发布补充（2026-10-22）：聚合证据见 [发布清单](../experiments/ranking_progress_2026_10_22/manifest.json)。属性 B 仍受后续发现的 raw author 0 契约问题影响，尚待新缓存消融；数值 A 不使用作者字段。见 [已知问题与研究方向](NEXT_RANKING_DIRECTIONS.md)。原历史结果保留不改；本次仅发布代码/报告，不上传新权重。

## 设计与最终样本

不换网络：A 为原 20 维统计 DCN，B 为 A 加作者/类目 embedding。不加入用户/物品 ID、历史或 DIN。每个架构有 5 种训练方式、每种 3 个种子，最终比较 30 个模型。前三个配对损失组使用相同初始化、端点和批次，避免把采样影响误认成 loss 的效果。

同用户固定 30 分钟桶内，用真实点击曝光配真实未点击曝光；不同物品、排除矛盾标签物品、折叠重复，负例允许重复使用。不跨桶、不跨用户、不使用未曝光候选当负例。训练 385577 对、17143 用户，验证 345061 对、7243 用户。没有推荐 request/slate ID；这些桶不是实际推荐请求。相同时间戳也仅能支持批次近似，不能恢复反馈到达顺序。

统一 5 轮上限，按固定验证配对的最低 softplus 损失选轮次；与上一轮按曝光 LogLoss 选型不同，因此重训 full_bce，而非直接借旧最优 checkpoint 比较。三种子来自同一验证日，不是三个独立数据划分。

full_mixed 是看到端点 BCE 的曝光 AUC 下降后、查看全量候选结果前固定的补充实验，不冒充最初预注册组；只用一个混合权重 0.5，不做权重搜索。其完整曝光批次/步数与 full_bce 相同，但每批额外前向配对端点，计算量更高。

观察：

- 配对端点采样在每个上下文形成正负平衡，改变了原曝光分布；全局 AUC 大降、用户内 GAUC 变化小，与用户间点击倾向信息受影响相符。不能把这部分变化都归因于排序损失。
- A 的完整曝光混合训练略降配对损失、基本保住曝光 AUC；相对 full_bce，配对损失的改善在 3 个种子均出现，但幅度小，尚不能仅凭该指标认定推荐提升。
- B 的完整 BCE 仍优于本轮其他 B 方案；完整混合组从首轮后就继续退化，按既定规则保留第 1 轮，未继续延长或回头搜索混合权重。
- 纯 pairwise 只约束分差，整体偏移不被识别，其 sigmoid 不自动是 CTR；端点 BCE 的平衡采样概率也不等于原流量 CTR。
- 冷物品曝光 AUC：A/full_bce 0.699850，A/pairwise 0.673021，A/full_mixed 0.699389；B/full_bce 0.708315，B/pairwise 0.655911，B/full_mixed 0.699968。不能把总体或单一排序代理变化写成所有人群均受益。

## 预设单种子级联对照

下表全部种子 2026，使用同一粗排和 2000→400→80→20 预算。召回命中均为 34647，粗排命中均为 9753；精排、重排结果如下：

| 配置 | 精排 80 命中 | 不做类别重排的 Top20 命中 / NDCG | 类别重排 Top20 命中 / NDCG |
| --- | ---: | --- | --- |
| A 完整 BCE | 1804 | 410 / 0.002488 | 433 / 0.002568 |
| B 完整 BCE | 1854 | 406 / 0.002714 | 439 / 0.002887 |
| B 端点混合 | 1850 | 309 / 0.001919 | 502 / 0.002947 |
| B 纯 pairwise | 1854 | 322 / 0.001984 | 422 / 0.002543 |
| A 完整曝光混合 | 1873 | 452 / 0.002745 | 441 / 0.002670 |
| B 完整曝光混合 | 1709 | 452 / 0.003061 | 492 / 0.003268 |

A 完整混合相对 A 完整 BCE，经过类别重排的最终命中只增加 8 次（433→441），明显小于直排平均增量；不能把直排收益直接写成完整链路收益。B 端点混合的重排后命中较好，但去重排则更差，提示相同 0.01 类别惩罚在不同分数标度下作用不同，不能全部归因于精排学得更好。纯 pairwise 的 sigmoid 不保证概率/分数标度可比。

这些级联是预设单种子对照，不是三种子稳定级联提升的证明。B 完整混合种子 2026 的级联较好，也不能覆盖它的三种子曝光退化、直排均值无收益的事实。默认模型不变。

## 验收与结论

99 项测试通过，依赖检查及 PowerShell 脚本语法检查通过。首次全套运行有一个既有 ItemCF 夹具在 Windows 目录重命名时遇 WinError 5；未改索引代码，随后两次全套重跑通过。保留这一环境波动，不声称定位了操作系统拒绝访问的根因。

最终 `artifacts/pairwise_final_v1/audit.json` 验证 30 个权重摘要、实际输入覆盖 mask、最低配对损失选型、checkpoint 重载预测、缓存 logits 重算配对损失、8495 用户唯一性和所有直排/级联逐用户命中汇总，全部通过；sigmoid 饱和行数为 0，旧 V1 冻结资产摘要不变。训练时间对齐在配对准备时全量重放，最终审计没有再次独立重放全部训练时间。

配对元数据 SHA256：`7b816b1fe8baef80d5e12efa70883f52e8d0f8e40e964165f2d545525c13c966`。候选 SHA256：`99abfbdb6e69d33264ae2b5c2a00031cf4edd8f984ef7e4c98054e861a73346e`。A_full_mixed_s2026 权重 SHA256：`b44b2763fe01b4f4c39d1720801917782e68a8f4928337501473b8f9862911a6`。

可选配置实际用户 20235 的四阶段推理已通过，输出 20 项；这是兼容性检查，不是新的延迟基准。全量评测使用批量缓存评分，不报告为服务 P95。

结论：pairwise 方向出现有限的离线排序信号，A 的完整曝光 BCE＋辅助 pairwise 是本轮较合理的保留方案，但尚不足以替换默认推荐。采样本身解释了 A 的一大部分直排变化，属性模型没有统一收益，级联增量有限且未跨种子验证，仍未超过简单 RRF/近期热门。后续优先做更可信的同批次上下文及新时间窗口复核，而不是在同一验证日无止境追加权重搜索。
