# 第二轮排查：时间、用户身份与搜索信号

本轮继续诊断，不重训、不调整生产参数、不访问最终测试标签。复用相同 8,495 名验证用户、固定候选与 DCN 权重。
候选 SHA256：`3d6b3da597395244bc998c1790cf3c380a9279c7ddde15523c540ade3c4ed764`；权重 SHA256：`d1cd761ef6f7f8ac6fcec8da058881bf138f4663bd4eb9b5e2a129bb9a8fbeca`。

## 1. 统一零点不是当前列表差距的主要解释

同一训练末特征快照和候选，只改变模型时间输入，不更新历史统计；每种时间都与同一完整验证日观察正例比较。这里是时间敏感性检查，不是恢复真实请求，也没有选择最优小时。

| 输入时间 | Top20 命中点击事件 | NDCG@20 | 相对零点 Top20 集合重合比例 |
| --- | ---: | ---: | ---: |
| 00:00 | 412 | 0.002632 | 100% |
| 06:00 | 406 | 0.002541 | 82.77% |
| 12:00 | 421 | 0.002591 | 78.23% |
| 18:00 | 425 | 0.002663 | 85.44% |

参考近期热门 NDCG 为 0.014684，以上时间变化不足以解释这一差距。时间会改变不少头部物品，但并没有让指标恢复到热门水平。
按 7,685 名有验证正例用户做配对 bootstrap，三个非零点方案相对零点的探索性 95% NDCG 差值区间全部包含 0；不代表任意真实请求时间都没有作用。

## 2. 模型并非完全不使用用户信息，但当前列表指标不敏感

先以种子 2026 对验证用户生成无自匹配的一一替换，再在原候选池中用另一用户的完整训练历史重算特征。物品、时间、候选与真实标签不变。
这不是新的推荐策略，只用于检查用户信息敏感性；替换后的输入对原用户不再真实，不能当作在线策略效果。

| 检查项 | 原用户 | 替换为另一用户 |
| --- | ---: | ---: |
| 全部实际曝光 AUC | 0.712655 | 0.584596 |
| 全部实际曝光 LogLoss | 0.619825 | 0.702283 |
| 池内有曝光候选 AUC（零点打分） | 0.676711 | 0.577145 |
| 全候选 NDCG@20 | 0.002632 | 0.002514 |
| Top20 命中点击事件 | 412 | 394 |

替换后 Top20 与原用户的平均集合重合比例仅 45.72%，完全相同顺序的用户仅 1.61%。模型输出确实依赖用户上下文，不能把它直接叫作“完全非个性化”。但这还不能分离用户总体点击倾向与兴趣匹配各占多少，更不能据此宣称个性化能力强。

配对用户 NDCG 差值为 -0.000118，探索性 95% bootstrap 区间为 [-0.000437, 0.000189]。用户信息被明显破坏后，曝光任务指标大幅下降，当前全候选观察命中指标却未给出清晰区分，进一步支持两种任务应分开评测。不能把“区间包含 0”写成两种用户历史效果等价。

## 3. 当前模型主要依赖统计特征，时间与搜索的边际信号很弱

固定种子抽 100,000 条真实验证曝光，基线 AUC 0.712257。对每一组特征做五次行置换，每次保留组内各列的共同取值，其他列不动：

| 被置换的特征组 | 平均 AUC 降幅 |
| --- | ---: |
| 用户 CTR、用户曝光量、已见用户标志 | 0.067897 |
| 类别与用户类别统计 | 0.059920 |
| 物品 CTR、物品曝光量、已见物品标志 | 0.035276 |
| 搜索统计四列 | 0.000472 |
| 时间周期四列 | 0.000347 |

置换会破坏跨组相关性，以上是已训练模型的敏感性，不是严格因果归因，也不是重新训练后的特征消融；各组降幅不能相加来分配模型收益。

## 4. 搜索信号：不是代码完全没接上，但没有显示稳定的大幅收益

验证曝光中有前一日搜索点击历史的记录 167,116 条，约占 23.03%，来自 2,963 名用户；无此搜索历史的记录 558,637 条，来自另外 5,532 名用户。

额外屏蔽搜索历史四列，使用与无搜索历史相同的有效输入：log 搜索次数与类别次数均为 0、平滑类别占比为 1/n_categories、has_search 为 0。推荐统计不变、不重新训练：

| 人群与指标 | 原始模型输入 | 屏蔽搜索历史 |
| --- | ---: | ---: |
| 全部曝光 AUC | 0.712655 | 0.713020 |
| 全部曝光 GAUC | 0.605471 | 0.605418 |
| 全部曝光 LogLoss | 0.619825 | 0.619835 |
| 有搜索历史曝光 AUC | 0.716169 | 0.717742 |
| 有搜索历史曝光 GAUC | 0.633616 | 0.633385 |
| 有搜索历史曝光 LogLoss | 0.614402 | 0.614444 |

无搜索历史人群的预测逐项完全不变；有搜索历史人群中，单条预测最大变化为 0.300639，说明模型计算路径确实能受搜索特征影响，而非这些列完全未接入。
总体 AUC、GAUC 和 LogLoss 的变化很小且方向不完全一致，不能宣称搜索信息必然有害，也没有证据宣称当前搜索分支已经带来明显收益。

目前搜索仅是前一已完成日的类别计数，没有搜索词语义、精确物品关联或行为顺序。时效不足、类别表达过粗、与推荐类别特征冗余、训练选择方式，都仍是候选解释，尚未通过重新训练消融区分。

## 接下来应验证什么

现有证据能弱化“零点打分导致灾难性失败”和“模型完全忽略用户”的解释，也指出当前搜索信号缺少已验证收益。
但**不能仅凭敏感性就确定具体新模型**。下一轮优先设计训练期内的配对、时间受控实验：

1. 在同一曝光与候选口径下，比较推荐统计基线和加入搜索的模型，重新训练并重复种子；同时报告搜索覆盖人群与无搜索覆盖人群。
2. 用真实曝光标签构造候选交集训练样本，观察用户内 GAUC 与已曝光候选排序；完整候选日志命中作为有偏覆盖辅助指标保留。
3. 再逐项引入近期热度、召回来源与名次、短期用户类别兴趣，避免同时换架构、样本和特征。

本轮未实施这些改进，也没有依据验证结果重新选择小时、参数或权重。

当前入口用于全量验证用户归档；曝光检查遍历全部验证曝光，用户替换映射必须覆盖这些用户。
主要原始产物：`artifacts/ranking_v3/sensitivity_valid_all/{metrics.json,per_user.json}`。源文件摘要、候选摘要、模型摘要保存在报告中。

搜索屏蔽对照可在同一权重上复算，以下代码不保存或修改任何模型：

```python
import numpy as np
import torch
from src.ctr_features import CACHE, FeatureState
from src.v2.train_rankers import Ranker
from src.ranking import metrics

torch.set_num_threads(4)
state = FeatureState.load(CACHE / 'state.npz')
x = np.load(CACHE / 'valid_X.npy', mmap_mode='r')
y = np.load(CACHE / 'valid_y.npy')
users = np.load(CACHE / 'valid_users.npy')
model = Ranker('artifacts/ranking_v3/fine_dcn/model.pt')
masked = np.array(x, copy=True)
masked[:, 16:18] = 0
masked[:, 18] = 1 / state.nc
masked[:, 19] = 0
original_p, masked_p = model.predict(x), model.predict(masked)
for group in (np.ones(len(y), dtype=bool), x[:, 19] > 0, x[:, 19] == 0):
    for p in (original_p, masked_p):
        result = metrics(y[group], p[group], users[group])
        print({k: result[k] for k in ('auc', 'gauc', 'logloss')})
```

新增 3 项单元测试覆盖无自匹配用户映射、组内联合置换/输入不变、配对 bootstrap 的确定性与边界；全套 71 项通过。
