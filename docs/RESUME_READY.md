## 推荐正文：四条版

### KuaiSAR 多路召回与内容增强推荐系统

技术栈：Python / PyTorch / NumPy / SciPy / SQLite

项目背景：基于约1066万条搜索与推荐交互构建离线实验系统，完成多路召回、曝光点击预测与候选排序对照。

- **召回质量优化：** 针对稀疏共现产生的弱支持候选，引入共同用户数阈值和TopK邻居截断，构建分块计算、内存映射的ItemCF索引；与近期热门融合，在95万训练点击物品库、固定2000候选预算下，开发Recall@2000由热门基线的9.42%提升至9.77%。
- **内容表示增强：** 为补充物品ID之外的内容信息，在575万条真实曝光上训练DCN，联合用户/物品ID、作者、类目与匿名caption词向量，并将未训练ID回退至UNK；同宽、同训练协议的三种子对照中，开发AUC由0.71985提升至0.72235，用户GAUC由0.61990提升至0.62301。
- **历史兴趣召回：** 在属性双塔中加入最近30条去重推荐点击的表示均值，采用批内对比学习训练64维用户/物品向量，支持95万物品的分块精确检索；三种子对照中，历史组纯双塔Recall@1000由属性组的1.30%提升至1.79%。
- **评估与方案取舍：** 按严格历史前缀构造样本，固定候选池对照LR/DCN、pairwise及兴趣表示，分别检查曝光预测、Top20覆盖和融合新增/挤出命中；定位局部模型增益未稳定传递至最终列表，按候选净增量与头部稳定性条件保留两路RRF作为默认。

## 版面紧张：三条压缩版

沿用上面的项目名和技术栈，以下三条可替换四条正文：

- **多路召回：** 基于95万训练点击物品，构建带共同用户支持度约束的分块TopK ItemCF索引，融合近期热门；固定2000候选的开发Recall@2000由9.42%提升至9.77%。
- **内容精排：** 在575万真实曝光上训练ID/属性DCN并加入匿名caption词向量，校验实际训练覆盖并回退未知ID；匹配协议三种子开发AUC由0.71985提升至0.72235，GAUC由0.61990提升至0.62301。
- **兴趣建模与验收：** 以最近30条去重点击均值增强64维双塔，纯召回Recall@1000由1.30%提升至1.79%；结合时间回放和融合新增/挤出分析，未因单路改善替换已有RRF强基线。

## 指标口径与职责边界（不贴进简历正文）

- 1066万为原始搜推交互规模，575万为推荐训练曝光量，95万为训练点击物品库；都不是线上服务规模。
- 9.42%→9.77%比较近期热门与近期热门＋改进ItemCF，使用同一开发日、物品库、用户和2000候选预算。支持度单因素实验的纯CF Recall@1000为3.4665%→4.0107%；不能把所有融合增益单独归给支持度阈值。
- AUC/GAUC比较同宽、同数据与训练协议的ID/属性组和内容组，取三个种子均值；内容收益属于曝光预测，尚未转化为超过RRF的Top20覆盖。
- 1.30%→1.79%比较属性双塔与增加推荐历史的双塔，使用各自选定检查点的主窗口纯召回指标。加入融合后Recall@2000为9.3326%，低于原9.7700%；Top20种子方向不一致，因此未采用双塔路。
- 所有新增指标均为离线开发验证或历史日期回溯，不是线上CTR、生产收益或新的盲测成绩。新版检索为冻结用户快照上的分块精确点积；caption是匿名词ID，不是预训练中文语义向量。
- 不新增“主导”“独立研发”“负责人”等个人职责身份。项目事实有代码/报告支撑，实际分工与掌握程度应按本人情况说明。
