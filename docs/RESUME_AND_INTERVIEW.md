# 简历与面试材料

项目名：基于 KuaiSAR 的搜索与推荐离线实验系统。

## 可使用的简历描述

- 基于 KuaiSAR-small 约 1,066 万条搜索/推荐交互构建 SQLite 数据管线，完成官方校验、字段/关联键审计、异常隔离和两场景共享时间切分；保留清洗原因及数据清单。
- 实现热门、ItemCF、双塔召回与候选融合，并完成 ID/历史/属性消融；验证集选择训练末日热门，在冻结测试集上取得事件 Recall@100 0.9160%，对照全时热门为 0.5628%。
- 构建按日期滚动的用户/物品/类别统计和搜索类别偏好特征，对比 LR、HGB、拼接与门控 MLP；推荐曝光测试 AUC 0.7091、用户 GAUC 0.5989、LogLoss 0.6226，平滑物品点击率基线 AUC 0.5699。
- 实现搜索会话结构化特征排序，测试正点击会话 NDCG@10 0.5050，对照常数分数/物品 ID 并列规则为 0.4596；完成类别重排、IVF-flat 与精确检索的质量/延迟对照，保存冻结配置、权重和独立复核记录。

简历空间有限时保留其中三条。需要先亲自运行并能解释关键代码，再使用“实现/构建”描述。指标须注明离线测试和对照，不能写成线上 CTR 提升或工业生产收益。

## 面试时应能解释

1. 为什么推荐 click 和搜索 click_cnt 不能直接混成同一 CTR 任务？搜索点击是在会话结果列表中，多个点击与零点击会话都要处理。
2. 为什么按全局时间切分？如何防止搜索与推荐间的未来行为泄漏？双塔历史严格早于目标，CTR 使用过去完整日期，测试固定 train 截止快照。
3. 冷物品为何限制召回？模型物品库只包含训练点击物品，新增视频不在库；应另设计具备可用时间约束的内容召回，不能提前拿测试物品拟合 ID。
4. 为什么 GAUC 比 AUC 低？全局用户点击倾向可提高 AUC，而组内排序提升较小；GAUC 还需要说明权重和有效组。
5. 为什么最复杂模型没有成为默认召回？实验表显示近期热门更适合当前静态短视频时间切分，复杂度不能代替验证结果。
6. 为什么搜索通道不能作为显著创新点？消融增益很小且单种子，门控与拼接接近，尚不支持强归因。
7. 为什么 CTR 更好但列表指标不一定更好？曝光分类与全库候选排序存在分布和目标差异，用户周期代理指标也不是实际请求指标。
8. 为什么不采用更快的 ANN？本机 IVF 达到所需重合率时更慢，保留精确；这是实现与硬件下的结果，不泛化成 ANN 无用。
9. 校准如何评估？同时报告 LogLoss、Brier 与 10 桶可靠性，常数概率可能 ECE 低但 AUC=0.5。
10. 如何证明结果不是挑出来的？先按验证集选择并保存 freeze.json，再运行测试；源码/模型摘要、候选和预测均保存，另行重算命中与概率指标。
