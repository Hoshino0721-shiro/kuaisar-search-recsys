# 排序优化：固定候选诊断与实施协议

后续[原因核验](RANKING_ROOT_CAUSE.md)补充了重要边界：DCN 在实际曝光候选上的预测与排序并未同样变差，全候选日志命中存在历史曝光策略偏差；不能仅据下方列表结果认定 DCN 模型无效。

## 本轮范围

先定位排序损失，再改特征，最后比较模型。保留 V1 冻结源文件、缓存和最终报告；不读取最终测试标签，不覆盖已有实验。

本地重新构建的 ItemCF 折中索引版本为 `2a04bafafdce84e2c413`，与远端报告一致，训练边 2,857,896 条、发布邻居边 247,832,193 条。
LR / DCN 基线按原默认配置恢复：相同种子 2026、相同 100 万训练曝光抽样、各 5 轮、验证 LogLoss 选 checkpoint。权重保存在 `artifacts/ranking_v3`，不会写入旧实验目录。

## 诊断协议

1. 用户集合固定：先按种子 2026 抽 256 名验证用户检查，再用全部 8,495 名验证用户复核；不按结果挑用户。
2. 候选固定：训练截止快照、热门/近期热门/改进 ItemCF、原 RRF 权重 1/2/1、候选上限 2000。每个用户只召回一次，全部排序方案共享相同物品集合。
3. 保存候选 JSONL、逐用户指标、候选文件 SHA256、模型 SHA256、配置、用户列表及请求时间，保证结果可核查。
4. 同 Top20 对照：RRF 原序、池内近期热门、池内全时热门、LR 直接排序、DCN 直接排序、LR 保留 200/400/800 后 DCN 排序。全部关闭多样性与作者约束，隔离排序本身。
5. 报告用户周期观察正例 NDCG@20、点击事件 Recall@20、粗排正例保留率、粗排保留 DCN Top20 的比例，以及有/无训练推荐点击用户分组。保留率随预算自然变化，不能只因低于 100% 就判定模型无效。
6. 未观察到点击的候选保持无标签；不能伪造曝光负例。标签 oracle 仅为池内二元 NDCG 上界诊断，不是可部署方案，也不是事件 Recall 上界。
7. 两个模型对完整候选池打分一次后复用分数，以便隔离截断损失；此计时不是多阶段服务的真实延迟。需要独立端到端重复压测才能比较服务成本。


## 全量验证诊断结果

本轮覆盖 8,495 名验证用户（有训练推荐点击 6,085 人，无训练推荐点击 2,410 人），正点击事件 354,626 次。
融合候选平均 1,818.81 个，覆盖正点击事件 29,530 次；候选 SHA256 为 `3d6b3da597395244bc998c1790cf3c380a9279c7ddde15523c540ade3c4ed764`。

| 同池 Top20 排序方式 | 命中点击事件 | 事件 Recall@20 | 正例用户 NDCG@20 |
| --- | ---: | ---: | ---: |
| RRF 原顺序 | 1707 | 0.481352% | 0.012979 |
| 近期热门顺序 | 1701 | 0.479660% | 0.014684 |
| 全时热门顺序 | 801 | 0.225872% | 0.005659 |
| LR 直接排序 | 548 | 0.154529% | 0.003586 |
| DCN 直接排序，无粗排 | 412 | 0.116179% | 0.002632 |
| LR 保留 200 → DCN | 388 | 0.109411% | 0.002529 |
| LR 保留 400 → DCN | 413 | 0.116461% | 0.002666 |
| LR 保留 800 → DCN | 415 | 0.117025% | 0.002661 |

LR 保留 200/400/800 时，分别保留池内正点击事件的 16.07%/30.25%/53.63%，以及 DCN 直接 Top20 的 73.69%/86.96%/96.97%。这里并未证明预算越大越好，尤其 400 与 800 的最终列表差异很小。

结论：绕过粗排仍远弱于简单排序，因此不能把主因仅归为粗排截断，当前 DCN 也不适合作为第一优先的蒸馏教师。近期热门的 NDCG 更高，RRF 的事件命中略多，二者存在指标取舍；未做显著性检验，不宣称它们之间有稳定胜负。

曝光分布上，恢复模型的验证 AUC 为 LR 0.707273、DCN 0.712655；曝光 AUC 优势没有转化为此候选池上的列表优势。结果支持优先检验时效与召回特征、训练/候选分布差异，但尚不能把缺少某个特征确认为唯一原因。

原始结果：`artifacts/ranking_v3/diagnostics_valid_all/{metrics.json,per_user.json,candidates.jsonl}`；小样本结果保存在 `diagnostics_valid_256`。
候选文件 SHA256、有/无训练点击用户分母加总、每种排序的分组命中加总均已独立核验。全套 64 项测试通过，含固定池、重复点击、空池、未来候选过滤、校验值与拒绝覆盖保护；V1 冻结资产摘要无变化。以上均为开发验证，不是最终测试或线上结论。

## 后续训练协议（待实施，不代表已有提升）

第一优先级是补充排序缺失的召回与时效信息，而非直接扩大网络：候选来源、各路名次/分数、近期点击热度、近期/长期热度比、用户近期类别偏好。先做 DCN 特征消融，再评估行为序列模型。

关键限制：不能将训练结束时的召回图用于更早训练曝光的召回特征；目标点击会进入图，造成泄漏。新增训练特征需要按日或滚动窗口构建严格早于样本的快照，在已记录曝光上计算特征与点击标签。候选来源覆盖率低时须报告匹配率和缺失规则，不能只保留命中正例。

建议在原训练期内划分较早训练窗口与较晚的内部开发窗口，先比较原特征与扩展特征的同架构 DCN；外部 May29 验证窗口保持候选生成一致。具体窗口与采样数在查看新结果之前写入实验配置。May30 及以后测试数据不参与本轮开发。

在内部开发窗口选模型和特征，在固定外部验证候选上比较列表质量；曝光验证另外报告 AUC、用户 GAUC、LogLoss、Brier。没有倾向概率或真实请求候选组时，不宣称无偏收益或线上 CTR 提升。

只有 DCN 在候选分布上成为更好的教师后，才优先考虑粗排蒸馏；DIN/序列特征需要截断前的历史、padding/mask、冷用户规则和参数/耗时对照。
