日期：2026-10-21。这是同一验证日上的开发实验，不是独立测试或线上 CTR 结论。实现和时间契约见 [实施说明](DCN_ENHANCEMENT_IMPLEMENTATION.md)。默认推荐和旧冻结权重不变；模型只接入独立实验入口。

## 曝光预测：三种子平均

各组共用固定 100 万训练曝光、725753 条验证曝光、5 轮上限、最低验证 LogLoss checkpoint。抽样种子 2026，训练种子 2026/2027/2028；3 种子不是 3 个独立时间窗口。GAUC 按曝光数加权，仅计同时包含正负标签的用户，有效 7345 用户、721659 条曝光。A/B/仅物品 ID 的 AUC 跨种子总体标准差分别为 0.000074/0.000739/0.000323，完整值与分组见本机 `summary.json`。

## 退化与适用范围

- C 退化后按预定规则执行 ID 拆分。用户 ID 不如 B；D/E 也没有超过历史父配置。保留全部种子和曲线，不只发布最优 checkpoint。
- 最低平均 LogLoss 的历史父配置为 `item_only`。最优单 checkpoint 是 `item_only_s2027`，AUC 0.716274、LogLoss 0.617419；它只用于约定的实验接入，不把最优种子当作三种子平均。
- 该 checkpoint 的训练 LogLoss 从第 2 轮 0.611445 降至第 5 轮 0.582877，同时验证 LogLoss 从 0.617419 升至 0.627571，明确存在后期过拟合，不应靠延长训练解释成收益。
- 冷物品（完整训练推荐曝光中未出现）AUC：A 0.699963、B 0.708315、仅物品 ID 0.708632；高频物品（训练曝光至少 20 次）AUC：A 0.702343、B 0.695846、仅物品 ID 0.693678。总体增益没有覆盖所有分组。
- 最终词表只拟合实际训练输入。验证推荐历史的非 PAD token 约 55.8% 为 UNK，搜索历史约 89.3% 为 UNK；不能通过使用验证 ID 扩词表来美化覆盖率。E 的负结果只约束此时间窗口、稀疏物品 ID、均值池化和训练协议，不证明搜索信息无用。
- 作者/类目没有历史属性快照，按静态属性假设使用。历史只取此前完整日期，反馈真实到达顺序仍不可验证。

## 全量同池与级联：没有支持切换默认模型

8495 用户共 354626 次观察正点击，所有模型对同一 2000 候选池直接排序。下表为三种子均值；命中是事件数，可为小数，NDCG 以有正点击的用户为分母。

| 直接精排配置 | Top20 命中事件均值 | 周期 NDCG@20 |
| --- | ---: | ---: |
| A | 373.33 | 0.002322 |
| 容量对照 | 379.67 | 0.002446 |
| B | 347.00 | 0.002195 |
| C | 486.00 | 0.003212 |
| B+仅用户 ID | 395.00 | 0.002515 |
| B+仅物品 ID | 288.00 | 0.001764 |
| D | 382.67 | 0.002387 |
| E | 324.33 | 0.002037 |
| RRF 候选原顺序（无训练种子） | 1745 | 0.014512 |
| 近期热门（无训练种子） | 1701 | 0.014684 |

曝光最优的仅物品 ID 配置在此列表指标上反而较差；C 的列表指标较 A 好，但曝光指标退化，且仍落后于 RRF/近期热门。不能在看过结果后改用列表指标挑种子，再冒充按原协议选中的赢家。

固定相同 LR 粗排和类别惩罚 0.01，对 A_s2026 与预定规则选中的 item_only_s2027 检查逐阶段命中：

| 阶段预算 | A_s2026 | item_only_s2027 |
| --- | ---: | ---: |
| 召回 2000 | 34647 | 34647 |
| 粗排 400 | 9753 | 9753 |
| 精排 80 | 1841 | 1770 |
| 重排 20 | 431 | 358 |
| 最终周期 NDCG@20 | 0.002573 | 0.002250 |

这支持“曝光预测的小幅收益没有转化成当前离线链路收益”，不支持默认切换。粗排截断同时移除了大量观察正例，但预算缩减本就会减少命中，不能仅凭减少比例判定实现错误；且直接精排也表现不佳，不能把全部问题归咎于粗排。

这些列表指标受历史曝光策略、固定截止快照和候选分布影响，不是无偏相关性或线上 CTR。现有证据指向曝光预测与候选列表目标不一致，新增稀疏身份表并未解决它。下一轮应优先设计新时间窗口及曝光支持范围内的排序验收，再决定目标、样本或表示变更，不继续靠堆叠 ID/历史追逐同一验证日。

先对每个用户平均 3 种子，再对 7685 个有正点击用户做 1000 次配对 bootstrap，得到探索性周期 NDCG 差异：

| 差异 | 均值 | 用户 bootstrap 95% 区间 |
| --- | ---: | --- |
| B−A | −0.000127 | [−0.000407, 0.000157] |
| 仅物品 ID−B | −0.000431 | [−0.000601, −0.000261] |
| D−仅物品 ID | 0.000623 | [0.000385, 0.000885] |
| E−D | −0.000350 | [−0.000491, −0.000211] |

D 的列表代理指标比父配置好，却有更差的曝光 LogLoss，进一步说明两类指标不能混为一个目标。这些区间未校正多重比较、没有独立时间窗口保证，不推断线上收益。

## 工程成本与入口

A 3557 参数、checkpoint 约 0.0185 MiB；B 327109 参数、约 1.29 MiB；仅物品 ID 6343333 参数、约 24.60 MiB。参数量包含分配的共享物品表，模型专用覆盖 mask 会将未实际拟合的 ID 回退 UNK，但未做表压缩。这些是权重文件大小，不是运行内存。

可选实验配置为 `configs/cascade_v2_enhanced_experiment.json`：

```powershell
.\.venv\Scripts\python.exe -m src.v2.enhanced_recommend --config configs/cascade_v2_enhanced_experiment.json --user-id 20235
```

依赖本机数据、匹配状态的粗排/基线权重、增强缓存和 checkpoint，不是新克隆即可运行的演示。增强入口核验缓存和状态摘要，不绕过远端权重与本机状态不匹配的问题。

### 实际请求验收（256 用户）

同一抽样种子 2026、同 256 用户、单进程 CPU 4 个 Torch 线程，真实执行召回、特征构造、粗精排和重排。各执行一次完整链路及去粗排/去重排对照，预热请求不计分位数；没有并行运行训练或测试。

| 指标 | 原数值 DCN | 仅物品 ID_s2027 |
| --- | ---: | ---: |
| 完整请求 P50 / P95（ms） | 8.02 / 70.92 | 13.80 / 106.54 |
| 精排阶段 P95（ms，含特征构造） | 1.18 | 2.96 |
| Top20 观察正点击命中 | 10 | 9 |
| 周期 NDCG@20 | 0.001951 | 0.001501 |

这是两次顺序运行的本机观测，缓存、调度和采样方差没有通过多轮交替测试控制，不能据此声称固定的减速倍数或生产 SLA。没有网络、并发和实时更新；完整用户质量判断以上述 8495 用户报告为准。增强进程观测工作集约 437.8 MiB，进程生命周期峰值 517.1 MiB，包含 Python/Torch、特征状态和 CF 映射页，不是单个模型内存。启动观测 29.07 秒（原入口 7.03 秒），包含校验和加载且受缓存影响，不能与预热后请求延迟混用。

在 4096 条验证输入上，实际原数值 checkpoint 与增强入口的 A_s2026 最大概率差为 1.19e−7，说明兼容恢复没有引入实质预测差异。独立增强入口保留，默认入口不变。

93 项测试通过，依赖检查通过，PowerShell 流水线语法检查通过。独立汇总核验 24 个 checkpoint 摘要、当前模型/训练源码摘要、数据版本、8495 用户唯一性、逐用户直排/级联命中汇总及旧 V1 冻结资产，全部通过。历史审计为全量字段对齐加确定性 SQL 抽查，不冒充所有历史行的独立穷举证明。

本轮执行到方案的实现、真实训练、分组/多种子评估、固定候选与真实推理验收结束。结论：保留属性增强的曝光预测证据及全部失败对照，不采用增强模型替换默认推荐；不再在本轮追加未预定的架构调参。源码与报告尚未提交或推送 GitHub。
