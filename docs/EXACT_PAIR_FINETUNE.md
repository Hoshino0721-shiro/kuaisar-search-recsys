# 同时间戳配对微调：预先固定协议（2026-10-22）

继续 [收敛补验](RANKING_CONVERGENCE.md)，不覆盖旧实验，不改默认 RRF，不读最终测试标签。仅在已验证的 R 数值 DCN 上做排序训练目标对照，没有增加网络、特征或额外负采样候选。

## 数据与分组

使用全量 5752167 条训练曝光。逐日按原 id 顺序 SQL 重放，逐行核对用户、物品、标签，再恢复训练时间戳；完整验证也逐行 SQL 对齐。记录实际使用的数值标签、用户/物品、验证时间戳、状态与新配对数组摘要。

同用户、完全相同的分发时间戳内构造配对。相同物品重复曝光且标签一致只保留最早一行；标签冲突的该物品全部行从配对中排除。每个正端点固定均匀抽取一个真实 click=0 物品，允许负端点复用。全量 BCE 仍使用所有原始曝光，不因配对去重删除原分类样本。

这些是同分发时间戳曝光组，不是已确认的真实 request/slate，也不保证反馈先后；不将未曝光候选标成未点击。匿名数据不能提供真实位置或 propensity，无无偏学习声明。

## 三臂匹配实验

三个种子 2026/2027/2028，各自使用上一轮通过审计的 R 最佳 BCE 权重（第 9/9/6 轮）初始化。新 Adam 从头建立、学习率 1e-4，属于明确的低学习率微调，不是假称旧优化器断点续训。

| 组别 | 损失 |
| --- | --- |
| bce | 全量曝光 BCE |
| endpoint_aux | 全量曝光 BCE + 0.2 × 正负端点平衡 BCE |
| pair_aux | 全量曝光 BCE + 0.2 × softplus(负 logit − 正 logit) |

同一种子的三组同步训练，始终共用完整曝光顺序、每批固定 1024 对的抽样、更新次数和学习率。端点辅助分类组隔离样本重复强调的作用。所有组进行相同的拼接输入前向，BCE 组不反传辅助损失。未进行辅助权重搜索。

每轮完整验证 AUC/LogLoss/GAUC/Brier、同时间戳曝光组 NDCG、固定验证对的 pair LogLoss/准确率；另记录固定 65536 条训练 probe LogLoss、固定 256 用户候选诊断。这些候选指标不参与选择。

## 选择、调度和早停

- 所有组使用相同标准：最小验证 pair LogLoss，但曝光 LogLoss 不得超过初始化 +0.0005，AUC 不得低于初始化 −0.001。初始化第 0 轮也是合法选择，避免强行接受退化模型。
- 选择标准相对上一轮从曝光 LogLoss 改为带保护条件的 pair LogLoss，因此必须与本轮相同标准的 BCE 对照比较，不能把相对旧权重的变化全归为 pairwise。
- 三组共享由 BCE 控制组的可接受 pair 验证走势驱动的学习率：连续 2 轮无超过 1e-5 的改善则减半，最低 6.25e-6。
- 最多 24 轮，至少 8 轮；只有三组都连续 4 轮无超过 1e-5 的可接受改善，且已经发生至少两次共同降学习率，才共同早停。若触及预算仍在改善，明确记为预算停止，不冒称收敛。
- 每轮单个原子 `last.pt` 同时保存三组当前/最佳权重、Adam、独立曝光/配对 RNG、历史、调度/早停计数和协议。最佳推理文件可从同一提交恢复，防止三组中途文件不同步。合成夹具验证续训与不间断训练逐位一致。

所选九个权重最终进行完整 8495 用户同池及级联评测，并独立审计。指标仍是复用开发日上的观察日志覆盖，不是线上 CTR 或新盲测收益。不自动替换默认、不自动推送 GitHub。

### 对照结论

1. **pairwise 相对本轮匹配 BCE 有额外开发收益。** 三个种子的直排差分别 +77/+47/+67，平均 +63.67；级联均值 +71.33。直排 NDCG 差 +0.000461，探索性用户 bootstrap 95% 区间 [0.000365, 0.000545]。
2. **但没有超过已有最佳权重，不能采用为新主方案。** 相比微调前，pairwise 直排均值 −7.33、级联 −24；周期 NDCG 仅 +0.000009，区间 [−0.000117, 0.000129] 跨 0；AUC 略降、LogLoss 略升。不是“pairwise 必然无效”，也不是“换 pairwise 已解决排序”。
3. **选择标准会改变比较对象。** 本轮继续 BCE 使用带保护线的 pair LL 选轮，而此前已有模型使用曝光 LL 选轮；相对旧模型的退化不能解读为任何继续 BCE 都必然退化。真正匹配的目标对照是本轮三组。
4. **不继续盲目追加训练预算。** 三组共用顺序、抽样、LR、更新次数，并满足预设的平台规则。当前结果不再能单纯归因于固定 5 轮没训练充分，但仍不证明所有网络、配对权重或优化方案的全局上限。

上述区间是先平均三个种子、再以用户为单位做 1000 次配对 bootstrap，仍是反复使用的开发日，无多重比较校正或独立时间窗口保证，不是跨种子或线上显著性。没有单独声明级联显著性。

### 额外特征可区分性检查

训练中 229073/2285174 对（10.02%）的全部 20+6 个有效输入完全相同；验证为 5562/284108（1.96%）。这些配对无法靠当前确定性网络区分，但占验证比例很低，**不能拿它解释整体候选排序瓶颈**。同用户同时间戳的用户级/时间级列本来相同，区分主要来自物品/类目统计和召回列；此检查是描述性信息，不是因果归因。
