# 双塔首轮验证（2026-10-15）

训练与评测：`python -m src.two_tower`。已有实验目录会拒绝覆盖；重复实验指定 `--run <新的目录名>`。

独立校验默认实验：`python -m src.audit_two_tower`。

记录位于 `experiments/r2_two_tower_valid/`，包含 config.json、metrics.json、audit.json、model.pt 和 candidates.jsonl。候选和权重是本地生成的大文件，按项目 .gitignore 排除。

## 模型和协议

用户 ID embedding → Linear → LayerNorm → L2 归一化；物品塔同结构。维度 32，温度 0.1，训练两轮，批大小 1024，种子 2026。ID embedding 使用 SparseAdam(lr=0.01)，投影层 Adam(lr=0.001)。固定使用第二轮，不按验证集选择 checkpoint。

训练只读推荐 train 的 2,860,013 条正点击事件；批内物品为对比学习的采样负例。重复物品以及同一用户在批内的其他点击目标作为正例，不视作曝光未点击。尚未加入负采样概率修正、类别、作者或行为历史特征；召回打分不作为 CTR 概率。

候选库为 951,625 个推荐训练期被点击物品，与全历史 ItemCF 共现物品库一致；未覆盖推荐 train 中仅未点击的物品。对验证正例事件的库覆盖上限为 54.6037%。按用户 ID 做精确余弦 Top100，不过滤历史物品，没有 ANN 误差。GPU 同分使用原生 topk，未承诺同分按物品 ID 排序或跨设备逐位确定性。

验证读取 rec valid 全部用户，且不更新参数。缺少训练点击历史的用户使用训练热门 Top100 兜底。测试交互未查询、未用于训练或选择参数。

## 指标

全量验证包含 8,495 位用户，354,626 个正例事件；其中 214,739 个正例事件的物品出现于完整推荐 train。主 Recall 为正例事件加权，重复交互计数保留。

| 方法 | Recall@50 | Recall@100 |
| --- | ---: | ---: |
| 双塔 + 无训练点击用户热门兜底 | 0.3378% | 0.5829% |
| 热门对照 | 0.5124% | 0.9362% |

全量双塔方案 Recall@100 为 2,067 / 354,626；训练已见物品分母下为 0.9626%。返回物品合计覆盖 221,009 个不同 ID。

| 用户分组 | 用户数 | 正例事件 | 双塔方案命中@100 | 热门命中@100 |
| --- | ---: | ---: | ---: | ---: |
| 有推荐训练点击 | 6,085 | 296,632 | 651 | 1,904 |
| 无推荐训练点击 | 2,410 | 57,994 | 1,416（热门兜底） | 1,416 |

有训练点击组双塔 Recall@100=0.2195%，同组热门=0.6419%。模型目前弱于热门，总命中中大部分来自兜底。不能把本方案总 Recall 与不带兜底的纯 ItemCF 直接比较并归因于双塔。候选来源和兜底一致后，才可做模型收益判断。

独立校验另给出用户在整个验证期内去重正物品的宏平均 Recall@100=0.9577%。这不是请求级 Recall，与事件加权主指标不可混用。

## 校验和成本

两轮平均训练 loss 为 6.5447、5.9240，下降只说明拟合目标改善，不代表召回已提升。使用 RTX 5070、PyTorch 2.8.0.dev20250611+cu128。单次记录训练约 18.08 秒，向量生成、全库精确检索、候选落盘及评测合计约 0.85 秒；没有逐请求同步计时和重复测量，不据此推算生产延迟或 QPS。

保存了代码、manifest、checkpoint SHA256。独立校验确认 checkpoint 摘要一致、可严格加载、向量有限；每用户 100 个候选且无重复，候选均来自训练点击物品库；用户集合完整，冷用户兜底列表正确；重算命中与 metrics.json 一致。19 项单元测试通过。

## 下一版优先项

加入训练期历史物品的聚合表示与物品静态属性，明确处理长尾 ID 的数据稀疏性；先保持同一候选库和兜底策略对比。新物品召回另设可用时间与缺失特征协议，再引入 ANN。当前实验只作为 ID 双塔的对照基线，不作为提升结果。
