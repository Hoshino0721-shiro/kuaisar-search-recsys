# 多阶段推荐算法改造

目标是搜推算法面试：能解释候选分布、各阶段模型、训练标签、逐阶段损失和效果成本取舍。当前 v2 已完成真实数据清洗、独立粗排/精排训练及 256 名验证用户的开发评测，四阶段级联可执行，效果尚未达到验收要求。它还不具备完整工业生产能力。v1 已冻结结果独立保留，v2 新模型没有沿用 v1 的指标。

## 首轮真实开发验证

官方 ZIP 大小 488,077,651 字节，MD5 校验通过。恢复审计后生成的数据清单 SHA256 为 `84bc856e6f1ee096e9bbf285db8c7fef2ed3832c561a8baa3f16498eafdf5a8f`，与 v1 记录完全一致。推荐训练曝光 5,752,167 条、验证曝光 725,753 条；两模型使用同一份 100 万条训练抽样，种子 2026，各训练 5 轮。正确性测试共 45 项通过。

| 模型 | 输入维度 | 参数量 | 验证 AUC | 验证用户 GAUC | 验证 LogLoss |
| --- | ---: | ---: | ---: | ---: | ---: |
| 独立 LR 粗排 | 8 | 9 | 0.707273 | 0.598045 | 0.627108 |
| DCN 精排 | 20 | 3,557 | 0.712691 | 0.605381 | 0.619798 |

原始报告：`experiments/v2_coarse_lr/metrics.json`、`experiments/v2_fine_dcn/metrics.json`。上表全部是曝光验证指标，不能与 v1 测试 AUC 直接比较并宣称提升。

256 名随机固定验证用户中有 9,554 个正点击事件，阶段预算与结果如下：

| 阶段 | 平均候选数 | 命中正事件数 | 保留前一阶段命中正事件的比例 |
| --- | ---: | ---: | ---: |
| 召回融合 | 1,842.55 | 748 | 不适用 |
| LR 粗排 | 400 | 224 | 29.95% |
| DCN 精排 | 80 | 50 | 22.32% |
| 类别重排与截断 | 20 | 9 | 18.00% |

相同 Top20 的用户周期观察正例 NDCG：近期热门 0.014423；完整四阶段 0.002233；绕过粗排 0.002857；关闭类别惩罚 0.002141。当前完整链路仍弱于近期热门，粗排造成明显的已知正例损失，精排的曝光 AUC 改善也未转化为列表收益。重排相对关闭惩罚时，类别多样性从 0.3184 变为 0.4125；这一小样本变化不构成统计显著性结论。

本机 CPU 单进程含检索和特征构造的请求 P95：完整链路约 52.86 ms、绕过粗排约 56.13 ms。这是单次开发测量，未重复压测、未计网络和并发，不据此宣称工业服务加速或 QPS。

级联报告：`experiments/v2_cascade_valid_256/metrics.json`。验证只抽样了 256 位用户，不能当作全验证集或最终测试结论。下一轮优先检查：召回来源与时效性信息在排序中的缺失、原始曝光与候选分布差异、候选相关的用户行为特征，以及粗排与精排优选候选的一致性；随后做保留预算、蒸馏、特征与重排参数的对照。当前不把“增加了阶段”当作效果改善。

## 现状和差距

2026-10-21 后续精排方案已细化为 [DCN 特征增强实验计划](DCN_FEATURE_PLAN.md)：先固定模型主干验证新增属性/身份信息，再验证具体历史行为。计划尚未实现或训练，不改变本文已有模型、结果与默认配置。

| 环节 | v1 已有 | v2 本次增加 | 仍待验证或建设 |
| --- | --- | --- | --- |
| 召回 | 热门、ItemCF、双塔对照；三路融合含双塔 | 三路可执行基线采用热门、近期热门、全历史共现 ItemCF，每路最多 1000，融合最多 2000；缓存共现图 | 改善双塔、接入可用时间受控的新物品内容召回；检验候选扩容质量 |
| 粗排 | 无独立模型 | 8 维低成本统计特征 LR，独立训练和模型文件，默认 2000→400，可真正绕过做对照 | 候选分布上的校正、精排教师蒸馏及校准；验证保留率与成本 |
| 精排 | 20 维统计特征门控 MLP | 原始向量参数 Cross Network + Deep 分支的 DCN，20 维数值输入，默认 400→80 | 与原 MLP 公平比较；加入类别/ID 字段及 DIN 行为序列，明确冷 ID 处理 |
| 重排 | 类别重复惩罚；冻结系数 0 | 复用类别贪心惩罚；执行器支持作者硬上限与约束不足时显式返回 shortfall，默认 80→20 | 参数在验证集选择；比较固定 Top20 的相关性、多样性和覆盖 |
| 评测 | 曝光 CTR 与用户周期列表指标 | 逐阶段正例保留、同一 Top20 口径 NDCG/Recall、单进程耗时；热门与绕过粗排对照 | 多种子、全验证集及新隔离测试窗口、更多分组、候选上限与错误案例 |
| 工程 | 本地 CLI | 带来源、数量、耗时、排除原因的结构化阶段轨迹；训练与推理快照校验 | 实时特征、在线反馈、API、网络/并发压测、上线 A/B；不属于本轮算法优先范围 |

这些数量是初始实验预算，不是统一工业标准，也不是已经选优的参数。小候选规模时粗排可能没有计算收益，应让成本与质量对照决定是否启用。多阶段系统还需要过滤、特征与训练服务一致性等环节，可参考 [NVIDIA 的推荐系统架构说明](https://docs.nvidia.com/deeplearning/performance/recsys-best-practices/index.html)。

## 可执行调用链

```text
官方 ZIP → v1 数据审计和 SQLite → v1 无目标标签泄漏的日级特征缓存
                              ├→ 8 维特征 LR 训练（粗排）
                              └→ 20 维特征 DCN 训练（精排）

离线用户请求
  → 训练快照热门 / 最后一天热门 / 全历史 ItemCF
  → 可用性与明确排除集合过滤、RRF 跨来源去重融合（≤2000）
  → LR 粗排（≤400）
  → DCN 精排（≤80）
  → 类别惩罚与可选作者约束（≤20）
  → 结果 + 来源 + 每阶段候选数/耗时/已知正例保留
```

当前 v2 使用 ItemCF 补齐三路基线，不声称已经把 v1 双塔升级为新模型。ItemCF 共现矩阵是训练期全部去重点击，查询是用户最近最多 30 个去重点击，减去对角自贡献并不等于过滤所有历史物品。冷用户该路为空，热门两路仍参与融合；不再给 ItemCF 路复制造一份热门以虚增 RRF 权重。

当前候选只来自训练期已点击物品，并按训练截止快照可用，不能在早于快照的请求上使用。代码中的未来候选过滤接口不代表已经实现动态新物品库。当前类别和作者继续按静态属性假设处理，数据缺少属性快照时间。

## 样本和模型契约

粗排、精排训练复用同一份原始推荐曝光的日级特征缓存，均匀无放回抽样最多 100 万条，不用未曝光召回候选伪造负标签。两个训练命令使用相同 seed 和 sample_rows 时抽样一致。标准化参数只在训练抽样上拟合。

粗排输入：用户 CTR、物品 CTR、类别 CTR、用户类别 CTR、log 用户曝光次数、log 物品曝光次数、长期类别占比、物品已见标志。粗排模型是独立 LR，不把 RRF 改名为粗排。

精排输入：原有 20 维推荐统计与搜索偏好特征。交叉层使用 `x_(l+1) = x_0 * (w_l^T x_l) + b_l + x_l`，与 20→64→32 的 Deep 分支拼接输出 logit。它是原始向量参数 Cross Network，不能写成 DCN-v2、DeepFM 或 DIN，也没有新增行为序列编码。

两个模型都用 BCE 训练，并在每个 epoch 计算验证 LogLoss，选择最低者。此处只完成曝光分布上的基础训练；粗排在实际召回分布上是否保住精排优选物品，需要额外评测。下一步可比较粗排蒸馏：用训练截止前、预留训练开发窗口的候选构建教师分数，用软标签训练粗排，不能拿最终测试结果反向教模型。

推理模型保存特征列、mean/std、训练/模型源码摘要、缓存和训练状态摘要。加载时核验两模型都来自当前特征状态。粗排推理具有独立 8 维计算路径，不计算搜索与时间周期特征；测试验证它和训练缓存所选列一致。精排只对保留的候选构造完整 20 维。仍需实测端到端耗时，不能只看模型参数量宣称加速。

## 评测与消融

第一轮先在固定随机种子的 256 个验证用户上检查流程，再扩到全验证用户。抽样实验只能作为开发检查，不能当全量最终结果。当前命令不开放测试集评测，避免在实现尚未收尾时反复查看测试结果。

必须比较：

1. 近期热门 Top20、全时热门 Top20。
2. 完整链路与真正绕过粗排的同模型链路。后者直接对全部融合候选做精排，记录质量和耗时。
3. 粗排预算 200/400/800。比较已知正例保留和最终 Top20 NDCG/Recall。
4. 固定召回及粗排，比较 v1 MLP 与 DCN；不预设新模型一定更好。
5. 重排 λ=0/0.01/0.03；相同输出数量下比较相关性、类别多样性和作者集中度。当前报告已实现类别多样性和 λ=0 对照，尚未汇总作者集中度。
6. 后续加入 ID/类别/序列特征时分别消融，避免同时改样本、特征与模型却无法归因。

当前报告实现了阶段预算下的正事件 Recall、前一阶段命中的保留比例、固定 Top20 事件 Recall、含正例用户的用户周期 NDCG@20；输出各阶段数量及 P50/P95。阶段预算不同，2000 项与 400 项的 Recall 不能直接作为模型优劣结论，主要用于衡量候选压缩损失。排序模型的曝光 AUC/LogLoss 另在训练报告中保存，选中 checkpoint 重载后另计算用户 GAUC、Brier 与 ECE（完整缓存具有 valid_users.npy 时）。

推荐日志没有完整的原始请求候选组和可用倾向概率，当前仍是一用户一固定列表的观察正例代理评测。不能把不存在日志点击的候选标为负类，也不能称为请求级线上 CTR、无偏策略收益或真实工业 A/B。若后续按时间窗口拼装伪请求，必须显式标注构造规则，不能假装恢复了原始请求。

重排前后应在同一个 K 比较；作者硬约束导致结果不足时，当前返回 shortfall，不偷偷放松限制。v2 初始实验类别惩罚为 0.01，报告包含同模型的 λ=0 对照；这不是已验证的最优参数，需根据验证相关性和多样性取舍后再冻结。v1 的系数 0 及冻结结果不变。

## 运行

在仓库根目录，使用项目独立 `.venv`。CPU 环境即可完成正确性验证，规模实验的耗时需实测。

```powershell
# 输入已就绪时一键构建数据、特征、粗排、精排、验证对照
./scripts/run_v2.ps1 -SkipDownload -MaxUsers 256

# 或分别运行
./.venv/Scripts/python.exe -m src.v2.prepare_data
./.venv/Scripts/python.exe -m src.ctr_features
./.venv/Scripts/python.exe -m src.v2.train_rankers --kind coarse_lr --out experiments/v2_coarse_lr
./.venv/Scripts/python.exe -m src.v2.train_rankers --kind fine_dcn --out experiments/v2_fine_dcn
./.venv/Scripts/python.exe -m src.v2.recommend --evaluate-valid --max-users 256 --compare-without-coarse --out experiments/v2_cascade_valid_256/metrics.json
./.venv/Scripts/python.exe -m src.v2.recommend --user-id 20235
```

`configs/cascade_v2.json` 是真实被 v2 CLI 加载的配置。新训练拒绝覆盖已有实验目录；开发中断时保留产物并使用新目录或人工核查，不自动删除。不得调用 v1 最终测试命令给 v2 调参；旧 freeze 和旧最终指标不属于新模型。当前没有 v2 最终测试冻结/验收报告，后续须在方案稳定后单独实现并选择未参与调参的保留窗口。

上述单步命令记录原实验路径。2026-10-21 起仓库发布 `experiments/v2_coarse_lr/model.pt` 和 `experiments/v2_fine_dcn/model.pt` 两个已有小型权重，校验值见 `experiments/published_artifacts.json`；复用它们仍须准备摘要匹配的特征状态。完整重训可使用一键脚本，它在独立的 `artifacts/v2_runtime` 下依据 `model.pt` 判断准备状态，生成运行配置并保存新权重及评测，不会自动复用这两份已发布权重。手动训练应另选不存在的输出目录，再通过 `--config` 指向新权重，不能覆盖旧报告。

后续全量召回优化、新双塔实现和未完成事项见 [当前进度](CURRENT_PROGRESS.md)。本文的 256 用户排序结果仍归属于首轮方案，不套用到新召回配置。

数据构建沿用 v1 清洗语义，通过 v2 包装器在歧义键表上补覆盖索引，避免千万级 UPDATE 的相关子查询逐行扫小表。原 v1 源文件保持不变。若完整原始记录已导入、审计阶段中断，可使用 `python -m src.v2.prepare_data --resume-audit`，它先验证官方 ZIP MD5、三张主表完整数量、SQLite 完整性及审计表存在，再继续索引和审计；存在已完成 manifest 时拒绝修改。附加索引不改变标签、时间切分或异常排除规则。

## 面试项目叙述

完成真实数据训练、消融和验收后，可以围绕这一问题组织叙述：在有限推理预算下，如何让粗排减少精排成本，同时保留足够的高价值候选，再通过重排平衡相关性与列表约束。

当前可描述执行器、模型实现、正确性测试和上文限定的256用户开发保留率；该小样本结果不是全量测试结论。尚不能说DCN已超过MLP、整体已经上线或形成工业收益。v1 的 AUC 0.7091 等数值继续只归属于 v1 门控 MLP。ItemCF后续索引化与全量验证见[独立报告](ITEMCF_INDEX.md)，不能直接当作级联最终Top20收益。
