# KuaiSAR 搜推一体化项目计划

> 初始路线归档：本项目已按 2026-10-22 [收尾范围](CLOSURE_PLAN.md) 完成，结论见 [v2 结项报告](PROJECT_FINAL_V2.md)。以下探索项不等于仍待执行任务，不自动继续扩展；后续 LLM 推荐另立项目。

## 1 项目定位

项目名称：KuaiSAR 搜推一体化多阶段系统

目标岗位：搜索算法、推荐算法、广告／内容排序算法、大模型与推荐交叉方向

项目目标：基于 KuaiSAR 构建一条包含召回、点击率预估、精排、重排和离线评测的完整链路，并研究搜索行为对推荐兴趣建模的帮助。

最终交付物：

- 可复现的数据处理和训练脚本
- 统一的 baseline 与改进模型实验表
- 搜索和推荐两类场景的分组指标
- 召回质量、排序质量、概率校准和延迟分析
- README、架构图、错误案例和简历项目描述

## 2 范围边界

### 第一版必须完成

- KuaiSAR 数据字段审计和数据版本记录
- 按时间切分训练、验证、测试数据
- 明确搜索和推荐事件的标签定义
- 热门召回、ItemCF 召回、双塔召回至少三种候选源
- 候选合并、去重和召回覆盖统计
- 一个 CTR 精排 baseline
- AUC、GAUC、LogLoss、Recall@K、NDCG@K、MRR 和覆盖率
- 端到端离线评测与延迟模拟

### 第二版再做

- 短期搜索意图与长期推荐兴趣的双通道建模
- 搜索与推荐多任务学习或门控融合
- hard negative 与曝光偏差处理
- 多样性、新鲜度和长尾约束
- FAISS 索引参数扫描
- FastAPI 服务和 Docker 化

### 不放进第一版

- 直接复现多个复杂论文模型
- 没有数据支持的线上 CTR 宣称
- 只改模型结构、不做完整 baseline 的“魔改”
- 依赖无法公开或无法复现的内部特征

## 3 阶段计划

### Phase 0 数据审计和环境准备

目标：确认 KuaiSAR 具体版本、文件结构、字段含义和标签可用性。

任务：

1. 记录数据下载来源、版本、许可证和文件校验值。
2. 统计用户、物品、查询、搜索行为、推荐行为和反馈事件数量。
3. 找出曝光字段、点击字段、停留或互动字段，并区分搜索与推荐场景。
4. 检查时间范围、重复日志、缺失值、用户冷启动和物品冷启动。
5. 产出数据字典和标签定义，未经确认的字段标记为待定。

当前已确认：推荐使用 `rec_inter.csv.click` 做隐式反馈／CTR 排序标签；搜索使用 `src_inter.csv.click_cnt` 做会话内点击排序标签。推荐数据的 `click=0/1` 约为 1:1，搜索约 60% 的会话包含至少一个点击。仍需对下载文件做本地统计和校验。

验收：任何 CTR 标签都能回指原始字段和定义；能生成一份小规模审计报告。

### Phase 1 可复现数据管线

目标：生成不泄漏未来信息的训练、验证、测试样本。

任务：

1. 以时间为主切分，避免随机切分造成用户未来行为泄漏。
2. 分别构造搜索排序样本和推荐排序样本。
3. 记录正负样本比例、曝光分布、场景分布和用户活跃度分布。
4. 固定数据版本和配置文件，所有实验复用同一测试集。

验收：重复运行得到相同样本统计和相同数据切分摘要。

### Phase 2 召回 baseline

目标：建立候选生成基线，并量化候选集质量和成本。

模型与策略：

- 热门召回：按场景和时间窗口统计。
- ItemCF：按用户历史行为构造相似物品。
- 双塔召回：用户塔编码历史行为，物品塔编码物品特征。
- ANN：先用精确检索验证质量，再接 FAISS 做延迟和内存对比。

指标：Recall@50、Recall@100、候选覆盖率、长尾覆盖率、候选数量、P95 延迟。

验收：每个召回源单独评测，并给出融合前后覆盖变化。

### Phase 3 CTR 精排 baseline

目标：完成点击率预估和列表排序的基础模型。

建议顺序：

1. Logistic Regression 或简单 MLP 作为概率基线。
2. DeepFM 或 DCN 作为特征交互基线。
3. DIN 或行为序列模型作为序列兴趣基线。

指标：AUC、GAUC、LogLoss、Brier score、校准曲线、NDCG@10、MRR@10。

验收：同一候选集、同一标签、同一测试集上完成模型对比；同时报告排序和概率质量。

### Phase 4 改进模型

目标：验证搜索行为是否能改善推荐场景的用户建模。

主假设：搜索行为通常更短期、更明确；推荐历史更适合表示长期兴趣。将二者直接混合可能造成兴趣污染，因此使用双通道表示和门控融合。

候选实现：

- 搜索短期兴趣塔
- 推荐长期兴趣塔
- 场景门控或意图门控
- 搜索与推荐多任务损失
- 近期搜索缺失时的退化策略

必须做的对比：

- 只有推荐历史
- 搜索与推荐直接拼接
- 双通道但无门控
- 双通道加门控
- 双通道加多任务损失

验收：总体指标、按是否有近期搜索行为分组的指标、冷启动和长尾指标都完成；有消融结论。

### Phase 5 重排、效率和服务模拟

目标：补齐工业系统视角。

任务：

- 加入重复惩罚、类别多样性、新鲜度和长尾约束。
- 对比不同融合权重和重排策略。
- 扫描 FAISS 索引参数，绘制 Recall—延迟—内存曲线。
- 提供本地推理接口，记录召回、精排、重排各阶段耗时。

验收：输出质量—成本 Pareto 表，而不是只给单一最高分。

### Phase 6 复盘和简历化

目标：把项目变成可面试、可核验的项目材料。

任务：

- 整理架构图、数据字典、实验表和失败案例。
- 对每个强主张保留实验配置和日志位置。
- 写出稳妥版和进取版简历描述。
- 准备召回、负采样、GAUC、校准、曝光偏差和延迟相关面试题。

验收：任何简历数字都能从实验记录复现；没有把离线结果写成线上收益。

## 4 指标口径

### 召回

- Recall@K：真实正样本是否进入候选集。
- Coverage：候选集覆盖的用户或物品范围。
- Long-tail coverage：长尾物品被召回的比例。

### 点击率预估与精排

- AUC：区分点击和未点击的排序能力。
- GAUC：按用户或请求分组后汇总的组内排序能力，报告分组权重。
- LogLoss：预测概率质量。
- Brier score 和校准曲线：概率是否可信。
- NDCG@K、MRR@K：列表前部的排序质量。

### 系统

- P50/P95/P99 延迟
- QPS 或批量吞吐
- 索引大小和模型大小
- 召回候选数与精排候选数

## 5 关键风险

### CTR 标签误读

KuaiSAR 的具体字段需要在 Phase 0 核对。未确认的未交互记录不能直接标记为曝光未点击。

### 时间泄漏

用户历史、物品统计和热门特征都必须只使用当前样本时间之前的信息。

### 采样导致概率失真

训练时可以做负采样，但测试集应尽量保留原始曝光分布；采样比例变化时，LogLoss 和校准结果需要单独说明。

### 指标归因错误

召回改进和精排改进必须分别报告。端到端收益不能直接归因给其中一个模块。

### 项目过度依赖框架

可以参考 MinionRec、RecBole 或 TorchRec 的工程组织，但核心数据切分、标签处理、模型和评测代码必须能由你解释。
