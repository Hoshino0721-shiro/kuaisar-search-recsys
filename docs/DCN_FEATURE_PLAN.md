# DCN 精排特征增强实验计划

日期：2026-10-21。状态：设计已确定，待实现和训练。本次仅提交计划，不修改默认模型、不运行训练，不将预期收益写成实验结果。

召回仍在继续优化，进展见 [取量、融合与共同用户支持度验证](RECALL_ALLOCATION.md)。本计划中“固定候选”用于隔离精排实验变量，不代表旧召回已验收完成；实际比较必须记录采用的索引、取量和融合版本。

## 目标与当前基线

保留原版 DCN 的 Cross + Deep 结构，通过分组增加输入信息，检验当前精排是否受限于 20 维统计特征。任务仍是对真实推荐曝光预测 click，不改成下一物品 ID 预测，也不为未曝光候选编造负标签。

当前基线为 `src/v2/models.py` 的 `FineDCN`：2 层原版向量参数 Cross、Deep 20→64→32，拼接后输出点击 logit；共 3,557 个参数。输入为 `src/ctr_features.py` 定义的 20 维数值特征，没有用户、物品、作者、类目的 embedding，也没有行为序列编码。

历史验证结果来自 `experiments/v2_fine_dcn/metrics.json`：使用 100 万条真实训练曝光，验证曝光 725,753 条，AUC 0.712691、用户 GAUC 0.605381、LogLoss 0.619798。这些是基线记录，不能提前归给增强模型。现有完整链路的开发结果及限制见 [CASCADE_V2.md](CASCADE_V2.md)。

待验证假设：

1. 作者和类目属性能提供 CTR 等统计量之外的信息，支持物品之间的信息共享。
2. 用户和物品 ID 能补充具体身份偏好，但可能因长尾稀疏而过拟合。
3. 具体历史点击物品能补充类目统计遗漏的兴趣信息。
4. 在已有搜索统计之外，历史搜索点击物品仍可能提供额外兴趣信息。

## 输入和网络设计

```text
原有 20 维数值特征 → 训练集拟合的标准化 ───────────┐
作者、类目、用户、候选物品 ID → 各字段 embedding ─┤
推荐历史物品 → 共享物品 embedding → masked mean ──┤
搜索历史物品 → 共享物品 embedding → masked mean ──┤
                                                  ↓
                                               拼接 x0
                                                  ↓
                                    2 层 Cross + Deep 分支
                                                  ↓
                                             logit / sigmoid
```

新增特征按实验开关逐步启用；原有 20 维统计特征全部保留。第一版维持 2 层 Cross 与 Deep 隐层 64、32，输入层和输出拼接维度随配置调整。Cross 仍使用 `x_(l+1) = x_0 * (w_l^T x_l) + b_l + x_l`，不改称 DCN-v2。

embedding 维度可先固定为用户 16、物品 16、作者 8、一级类目 8，作为开发起点，不宣称已选优。ID 不作为连续数值直接送入模型；embedding 与 DCN 联合训练，只标准化数值分支。

推荐和搜索历史分别聚合，保留场景区别；候选与两类历史共享物品 embedding 表。首版使用最近最多 30 条合规正点击记录，允许重复点击，不把均值池化称为顺序建模。记录有效长度、空历史和 UNK 比例；给下游的长度/空历史标志属于对应历史特征组，消融时一起移除。空历史返回零向量，padding 不参与均值。候选相关 attention、时间衰减和更长历史在均值基线之后单独比较。

## 实验矩阵

| 编号 | 输入或改动 | 要回答的问题 |
| --- | --- | --- |
| A | 现有 20 维统计 DCN | 在相同样本和训练协议下复现基线 |
| A-capacity | 仅统计特征，适当增加 Deep 宽度 | 部分收益是否仅来自容量增加？ |
| B | A + 作者、一级类目 embedding | 属性能否提供额外信息？ |
| C | B + 用户、物品 ID embedding | 身份信息是否有效，是否伤害长尾和冷物品？ |
| D | C + 推荐历史物品均值池化及长度/空历史标志 | 具体推荐历史是否有效？ |
| E | D + 搜索历史物品均值池化及长度/空历史标志 | 在已有搜索统计外，搜索历史是否有效？ |

首轮只实现和比较 A、A-capacity、B、C；第二轮再实现 D、E。A-capacity 的宽度和训练预算提前写入配置，作为容量诊断，不假装能够完全匹配 embedding 的参数结构和归纳偏置。若 C 退化，先做仅用户 ID、仅物品 ID 的拆分消融，再决定是否在行为实验中沿用全部 ID 字段。后续分支必须明确写出实际父实验。

不要在首轮同时切换 DCN-v2、DIN、更大的训练样本、损失函数或召回配置。D/E 有效后，再在同输入、同历史窗口上比较均值池化与候选相关 attention，检验兴趣提取方式的价值。

## 数据字段与时间契约

- 复用官方 KuaiSAR-small、现有清洗规则和共享时间边界：训练 `< 2023-05-29`，验证 `[2023-05-29, 2023-05-30)`，均为北京时间。推荐标签使用原始 `click`。
- 数据库已有 `users.user_id`，以及 `items` 中的物品 ID、作者、一级类目；现有数值缓存不包含新增类别字段，需另建带版本的缓存。
- 用户活跃度、更细类目和匿名文本未全部落入现有数据库；如以后使用，需从原始文件单独提取、审计，不能假设当前缓存已具备。
- 作者、类目按现有静态属性假设使用，并记录没有历史属性快照这一限制。物品特征缺失不删除曝光，使用缺失标志和 UNK。
- 词表、ID 频次、低频阈值所依赖的统计和数值标准化参数只在训练部分构建。验证新 ID 不能预分配一个未经训练的独立 embedding。
- 建议 PAD=0、UNK=1，正常 token 从 2 开始；PAD 与 UNK 语义分离。低频阈值作为配置记录，初始值在训练前固定；如调参只使用开发验证集。
- 历史仅使用合规的正点击；搜索历史采用 `click_cnt > 0` 的物品记录，不把计数当作推荐标签。
- 为与 A 保持时间信息边界一致，首轮训练历史仅取此前完整日期；验证历史冻结在训练截止点，不在验证期滚动更新。E 的搜索物品历史先与现有搜索统计对齐为前一完整日窗口，推荐历史取截止点之前最近 30 条；两路均记录实际窗口。
- 推荐时间是分发时间，搜索时间是会话时间，不能恢复精确反馈到达顺序。同时间记录作为并列事件，不把排序用的 item_id/源行号解释成真实先后；截断时采用固定、可复现的并列处理规则并记录。
- 不将当前曝光的点击、点赞、播放反馈，或预测时刻之后的搜索行为作为当前输入。更实时历史和反馈可用时刻假设另立实验，不与本轮表示增强混在一起。

## 公平训练与证据记录

1. 各实验使用同一份 100 万条训练曝光 ID 清单；抽样种子固定 2026，清单保存校验值。训练随机种子与抽样种子分开配置，重复训练时不改变样本。
2. 维持同一标签、损失 BCE、batch size、训练轮数上限和优化器协议；参考当前基线为 batch 4096、5 轮、Adam。所有不同之处写入配置，不沿用旧 checkpoint 的标准化或模型参数伪装成公平重训。
3. 各实验按相同规则选取最低验证 LogLoss 的 checkpoint。先单种子初筛，有希望的配置再用至少 3 个训练种子复核，同时复核 A。
4. 保留 A 的历史产物；新增缓存、词表、模型和报告写入独立版本目录，拒绝覆盖。默认级联仍指向原有 DCN，待结果通过评审再单独切换。
5. 保存样本清单、数据清单、代码版本、词表、特征 schema、历史窗口、缺失策略、模型配置和 checkpoint 的校验信息，推理加载时核验一致性。

## 评测与判断规则

曝光预测报告至少包括 AUC、用户 GAUC、LogLoss、Brier/ECE，以及训练与验证差距。保留 GAUC 的用户过滤、加权方式及有效用户数；不能只报告较好看的一个指标。

分组报告训练已见/未见物品、低频/高频物品、用户活跃度、空/非空推荐历史、有/无搜索历史。分组阈值依据训练统计预先固定。全量验证及分组结果同时保留，避免平均提升掩盖冷物品退化。

列表评测固定 ItemCF 索引、召回配置、候选集合和 TopK，比较精排分数决定的排序。先在同一候选池直接比较精排，隔离粗排干扰，再接回同一粗排、重排配置检查逐阶段正例保留及最终 Top20。报告 NDCG/Recall、特征构造和推理 P50/P95、参数量及内存成本。

列表指标仍是固定历史快照下的用户周期观察正例代理指标，不称为逐请求下一点击指标、无偏策略收益或线上 CTR。未观察到点击的召回候选不能直接标成负例。新增身份或历史特征也不能解决当前训练曝光与召回候选之间的分布差异。

本轮只做验证期开发。旧 v1 测试已被查看，不能把反复使用它后的结果称为新的独立最终测试；最终确认需要预先声明的新隔离窗口或明确披露测试复用限制。

验收依据是可复现、跨种子方向稳定的验证收益及成本取舍，不预设 AUC 涨幅：

- B/C 稳定改善，并经容量对照和分组检查支持，才说明新增属性/身份信息有帮助。
- D 在父实验上继续改善，才支持进一步研究候选相关历史建模。
- E 改善只能说明在现有搜索统计上增加搜索点击历史的价值；若要证明全部搜索信息的价值，还需移除原有 4 维搜索统计的对照。
- 若新增特征无收益，先检查覆盖率、UNK 比例、稀疏性、时间对齐、过拟合和优化设置，不能据此直接宣称统计特征已经充分。
- 曝光指标改善而同 K 列表无改善时，保留该结论并检查候选分布和粗排损失，不宣称推荐链路已经提升。
