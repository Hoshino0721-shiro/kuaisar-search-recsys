## 标签规则

推荐 CTR／隐式反馈任务：使用 `rec_inter.csv` 的 `click` 作为标签。官方说明推荐数据中 `click=0` 与 `click=1` 的比例约为 1:1，并建议用 `click` 区分正负样本。这个标签仍需在本地审计中确认缺失值和取值范围。

搜索排序任务：使用 `src_inter.csv` 的 `click_cnt` 作为会话内展示物品的点击标签。搜索会话可能包含多个点击，约 60% 的会话包含至少一个点击；因此搜索任务应以会话内排序为主，不直接套用推荐 CTR 的独立样本假设。

如果为了训练做额外负采样，必须保留原始 `click` / `click_cnt` 标签和采样比例。训练采样后的概率不能直接当作原始流量 CTR，验证和测试要固定候选集与标签口径。

官方还指出，推荐系统中 `search` 和 `search_item_related` 只记录用户观看推荐视频时点击放大镜发起的主动搜索；搜索结果可能包含非视频类型，而推荐系统主要推荐 `VIDEO` 或 `IMAGE_ATLAS`。这些字段会用于场景和跨服务特征，但不能混成同一个 item 集合而不做类型过滤。

## 时间切分规则

### 2026-10-14 全量核验补充

推荐 `timestamp` 与搜索 `search_session_timestamp` 均为整数毫秒，全部与 UTC+8 文本时间相符。正式管线应保留整数毫秒，不使用原型中未声明单位的数值时间。

搜索有 132,869 条交互缺少物品特征，应采用 left join 和缺失标志。23 个物品类型异常值保留原始值，不猜测修复；11,901 条 1970-01-01 上传日期不直接作为新鲜度依据。4 个搜索会话字段不一致仍待定位。详见 SECOND_DATA_AUDIT.md。

主方案为搜索、推荐共用全局显式时间边界；具体边界和时间戳单位待本地审计。相同时间不得分到两侧；搜索会话跨界时先报错并审计，不静默拆分。所有历史特征还必须单独保证严格早于预测时刻，切分本身不保证特征无泄漏。

可考虑的敏感性分析：

1. 全局时间切分：最后一段时间作为测试集。
2. 用户内时间切分：每个用户最后一次或最后若干次行为作为测试集。
3. 搜索与推荐独立时间切分：避免场景之间通过未来行为泄漏。

独立场景切分不得用于跨场景主结果，否则可能混入另一场景的未来行为。
